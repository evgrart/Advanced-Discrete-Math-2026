# Система оценивания по дискретной математике

Инструкция по запуску с нуля.

## 1. Что лежит в папке

- `ДМ_система_логи.xlsx` — чистый шаблон таблицы.
- `Code.gs` — код Google Apps Script.
- `build_compact_workbook.py` — генератор XLSX, если понадобится пересобрать шаблон.

## 2. Запуск в Google Sheets

1. Откройте Google Drive.
2. Загрузите `ДМ_система_логи.xlsx`.
3. Откройте файл через Google Sheets.
4. Переименуйте таблицу при необходимости.
5. Откройте `Расширения → Apps Script`.
6. Удалите содержимое стандартного файла `Code.gs`.
7. Скопируйте туда весь код из локального `Code.gs`.
8. Нажмите «Сохранить».
9. Вернитесь в таблицу и обновите страницу.
10. В меню появится `DM система`.

При первом запуске выберите `DM система → Установить проверки и цвета` и подтвердите разрешения Google.

## 3. Листы

- `Общий` — список студентов, их практик, статус `Прод`, D, CW и текущий тир. Порядок первых колонок: `ФИО → Практик → TG`.
- `CW` — две контрольные работы, `КР-1` и `КР-2`.
- `Рейтинг` — автоматически сортируемый список активных студентов по D и CW. Колонки: `ФИО → Практик → TG → D → CW → Тир`.
- `Логи` — журнал выходов, штрафов и ухода на базу.
- `Плюсы_Артём`, `Плюсы_Рами`, `Плюсы_Немат` — по одной таблице на каждую практику у каждого практика.

Верхние декоративные строки с названиями листов убраны: рабочая таблица начинается сразу с заголовков.

## 2.1. Кнопки меню `DM система`

- `Установить проверки и цвета` — запускать один раз после импорта. Устанавливает допустимые значения, цвета ячеек и пересчитывает систему.
- `Синхронизировать группы` — переносит студентов на плюсовики согласно колонке `Практик` на листе `Общий`. Отмеченные задачи сохраняются по ФИО.
- `Синхронизировать таблицу` — одновременно обновляет скрытие/возврат студентов, D, CW, тиры и лист `Рейтинг`.

## 4. Первичная настройка студентов

На листе `Общий` для каждого студента заполните:

- `Практик`: `Артём`, `Рами` или `Немат`.
- `ФИО`.
- `TG`, если нужен.
- `Прод`: обычно `Да`.

После изменения практикующего нажмите `DM система → Синхронизировать группы`.

При синхронизации студент переносится между плюсовиками, а его отмеченные задачи сохраняются по ФИО.

Не переименовывайте листы и не меняйте расположение колонок без изменения `Code.gs`.

## 5. Работа с плюсовиками

В единственной таблице каждой практики выпадающего списка нет. Студент вручную вводит `'+` напротив решённой задачи. Практик вручную вводит `1` или `-`.

В Google Sheets обычный символ `+` иногда воспринимается как начало формулы. В этом случае вводите его с апострофом: `'+`. Апостроф не отображается в ячейке, в ней останется обычный `+`.

Практик может заменить `+` на:

- `1` — студент вышел и решил задачу. Система добавляет запись в `Логи` и начисляет D по лестнице с коэффициентом.
- `-` — студент рассказал откровенную лажу. Система начисляет ровно `−2` балла без коэффициента; колонка `Статус` при этом остаётся пустой.

Очистка ячейки удаляет соответствующую запись из логов и пересчитывает D.

Цвета:

- `+` — светло-зелёный;
- `1` — тёмно-зелёный с белым шрифтом;
- `-` — красный.

За одну практику студенту назначается не больше двух выходов. После 15 обычных выходов запись получает статус `Дополнительный выход`; базовые баллы лестницы после 15 равны нулю, а возможные дополнительные баллы можно внести через поправку в логах.

## 6. Лестница и коэффициент D

Номер выхода студента считается по всем обычным выходам:

| Выходы | База D |
|---|---:|
| 1–3 | 6 |
| 4–6 | 5 |
| 7–9 | 4 |
| 10–12 | 3 |
| 13–15 | 2 |
| после 15 | 0 |

Коэффициент пересчитывается отдельно для каждой практики:

- больше `2x/3` плюсов — `1`;
- от `x/2` до `2x/3` включительно — `0.8`;
- меньше `x/2` — `0.5`.

Здесь `x` — количество задач практики, а считаются только значения `+` и `1`. Значение `-` в коэффициент не входит.

Формула начисления обычного выхода:

`База D × коэффициент + Поправка`.

Штраф `-2` коэффициентом не умножается.

## 7. Логи

В `Логи` записи создаются автоматически. Колонки идут в порядке:

`ФИО → Практик → Практика → Задача → Номер выхода → База D → Коэффициент → Начислено D → Статус → Поправка → Дата`.

Если на листе `Общий` изменить `Прод` с `Да` на `Нет`:

1. студент скрывается на всех трёх плюсовиках;
2. в `Логи` добавляется запись со статусом `ушел на базу`;
3. старые баллы и логи сохраняются.

Если вернуть `Прод = Да`, студент снова показывается. Логи при этом не скрываются и не удаляются.

Если изменить `Практик`, в логах появится запись со статусом вида `переведен из Артём в Немат`. После изменения запустите `Синхронизировать группы`.

## 8. CW

На листе `CW` есть `КР-1` и `КР-2`.

- `Попытка` — целое число от 1 до 4.
- Баллы каждой задачи — от 0 до 4.
- `S` — сумма баллов контрольной.
- Общий CW студента складывается из результатов двух контрольных.

Менять номер контрольной нужно только в заголовке `КР-1` или `КР-2`, а не в строках студентов.

## 9. Тиры

Тир считается только по D и CW:

| Тир | Условие |
|---|---|
| S | D ≥ 55 и CW ≥ 24 |
| A | D ≥ 35 и CW ≥ 14 |
| B | D ≥ 17 |
| Допса | условие B не выполнено |

Проверка идёт сверху вниз: сначала S, затем A, затем B.

Оценка по таблице и финальная оценка автоматически не считаются и в текущем шаблоне не используются.

## 10. Рейтинг

Лист `Рейтинг` обновляется автоматически после изменения D, CW, плюсов, единиц, минусов, поправок в логах или статуса `Прод`.

Студенты с `Прод = Нет` из рейтинга исключаются. При возврате `Прод = Да` они снова добавляются автоматически.

Сортировка:

1. D по убыванию;
2. CW по убыванию;
3. ФИО по алфавиту.

Если нужно принудительно обновить данные, выберите `DM система → Синхронизировать таблицу`.

## 11. Ограничение 1 и - только для практиков

Google Sheets не умеет в одной и той же открытой ячейке разрешать студентам только `+`, а практикам дополнительно `1` и `-` без определения пользователя.

В начале `Code.gs` есть настройка:

```javascript
practitionerEmails: []
```

Для ограничения впишите email практиков:

```javascript
practitionerEmails: [
  'artem@example.com',
  'rami@example.com',
  'nemat@example.com'
]
```

После изменения кода сохраните его и обновите таблицу. Если список пустой, `1` и `-` технически доступны любому редактору таблицы — это оставлено для тестирования.

## 12. Одновременная работа

Три практика могут работать одновременно. Код использует блокировку документа при добавлении и удалении записей в логах, чтобы два действия не заняли один и тот же номер выхода.

Не запускайте одновременно ручную синхронизацию групп, пока другой практик массово редактирует плюсовик.

## 13. Если нужно пересобрать XLSX

В папке проекта выполните:

```text
python build_compact_workbook.py
```

Будет пересоздан файл `ДМ_система_логи.xlsx`.

После повторного импорта XLSX в Google Sheets снова вставьте актуальный `Code.gs` и один раз запустите установку проверок и цветов.

Перед пересборкой сохраните рабочую Google-таблицу отдельно: генератор создаёт чистый шаблон и не переносит текущие баллы и логи.
