# ДМсистема

Система состоит из четырёх отдельных Google-таблиц:

- `ДМобщее.xlsx` — центральный файл;
- `ДМАртём.xlsx` — плюсовик группы Артёма;
- `ДМРами.xlsx` — плюсовик группы Рами;
- `ДМНемат.xlsx` — плюсовик группы Немата.

Каждый файл практика содержит 15 отдельных листов: `Практика 1`, `Практика 2`, …, `Практика 15`. На каждом листе находится одна таблица соответствующей практики. Центральный файл не содержит плюсовиков.

## 1. Установка

1. Загрузите все четыре XLSX в Google Drive.
2. Для каждого файла нажмите правой кнопкой мыши → `Открыть с помощью` → `Google Таблицы`.
3. В открывшемся файле выберите `Файл` → `Сохранить как Google Таблицу`. Должна появиться новая Google-таблица без зелёной метки `.XLSX`.
4. Открывайте Apps Script уже у созданной Google-таблицы, а не у XLSX-файла. Только после конвертации появляется меню `Расширения`.
5. Не переименовывайте листы:
   - центральные: `Общий`, `CW`, `Рейтинг`, `Логи`;
   - файлы практиков: листы `Практика 1` … `Практика 15`.
6. Откройте Apps Script именно из сконвертированного центрального файла `ДМобщее` через `Расширения → Apps Script`.
7. Замените содержимое `Code.gs` кодом из локального файла [Code.gs](Code.gs).

В начале `Code.gs` заполните четыре ID:

```javascript
centralFileId: 'ID_ДМобщее',
plusFileIds: {
  'Артём': 'ID_ДМАртём',
  'Рами': 'ID_ДМРами',
  'Немат': 'ID_ДМНемат'
}
```

ID находится в URL Google-таблицы между `/d/` и `/edit`.

Например:

`https://docs.google.com/spreadsheets/d/ABC123/edit`

ID — `ABC123`.

После заполнения:

1. Сохраните Apps Script.
2. Вернитесь в `ДМобщее` и обновите страницу.
3. Откройте `DM система → Настроить 4 файла`.
4. Подтвердите все разрешения Google.

Эта команда создаёт триггеры на всех четырёх таблицах. Без неё изменения в отдельных файлах практиков не будут передаваться в центральный файл.

## 2. Кнопки

Меню `DM система` доступно в центральном файле.

- `Настроить 4 файла` — устанавливает триггеры, синхронизирует группы и пересчитывает систему. Запускается после импорта или изменения ID.
- `Синхронизировать группы` — переносит студентов между тремя файлами практиков согласно колонке `Практик` в `Общий`. Плюсы, единицы и минусы сохраняются по ФИО; если ФИО ещё не совпадают, дополнительно используется прежняя позиция строки. Несинхронизированные `1` и `-` восстанавливаются в `Логах`.
- `Синхронизировать таблицу` — выполняет полную синхронизацию групп, D, CW, тиров, рейтинга и скрытия студентов. Старые заметки-комментарии из ячеек задач удаляются.
- `Применить количество задач` — перестраивает столбцы задач у всех трёх практиков по конфигу `practiceTaskCounts`, обновляет формулы S, коэффициента и подсветку, затем синхронизирует систему.
- `Telegram-бот` — подменю настройки webhook и проверки конфигурации. Оно появляется после добавления `TelegramBot.gs` из отдельного приватного репозитория [Distribute-tasks-bot](https://github.com/evgrart/Distribute-tasks-bot) в тот же Apps Script-проект.

## 3. Центральный файл `ДМобщее`

### `Общий`

Первые колонки:

`ФИО → Практик → TG → Прод → D → CW → КР-1 → КР-2 → Тир → Бонус к CW → Бонус к D → Экзамен → Задача → Итоговая оценка`

`Бонус к CW` и `Бонус к D` — ручные числовые поправки преподавателя только для определения тира. Отображаемые `D` и `CW` остаются фактическими баллами без бонусов. Тир проверяется по `D + Бонус к D` и `CW + Бонус к CW`. `Итоговая оценка` рассчитывается автоматически по текущему тиру и оценке за экзамен.

`КР-1` и `КР-2` автоматически показывают `зачет` или `незачет`. Если обе контрольные зачтены, строка студента подсвечивается зелёным.

`Задача` — ручной статус задачи Карпова: `решена`, `не решена` или пусто. Для итоговой оценки используется нижняя оценка из пары при пустом статусе или `не решена`, и верхняя оценка из пары при `решена`. Например, `3D/4C` превращается в `3D` или `4C`, а `4B/5A` — в `4B` или `5A`.

Пока у студента нет двух зачётов за КР (`КР-1` и `КР-2`), итоговая оценка принудительно равна `2F`.

Если изменить `Практик`, центральный скрипт:

1. записывает событие в `Логи` со статусом `переведен из ... в ...`;
2. переносит студента в новый файл практика;
3. сохраняет его плюсы.

### Переименование студента

ФИО можно изменить в столбце `ФИО` на листе `Общий` или в столбце `ФИО` нужного плюсовика. При обычном изменении одной ячейки скрипт обновляет имя в центральной таблице, всех плюсовиках, КР, рейтинге и логах. Если такое ФИО уже занято, изменение отменяется. Очищать ФИО нельзя — нужно указать новое имя.

Если установить `Прод = Нет`:

1. студент скрывается в соответствующем файле практика;
2. в `Логи` появляется запись `ушел на базу`;
3. старые плюсы и баллы сохраняются.

При возврате `Прод = Да` студент снова показывается.

### `CW`

В таблице есть два блока контрольных работ. Перед каждым блоком указано `КР-1` или `КР-2`; эти подписи не входят в закреплённую область. Сверху закреплена синяя шапка.

- `Практик` — практик студента;
- `Попытка` — целое число от 1 до 4;
- каждая задача — от 0 до 4 баллов;
- `S` — взвешенная сумма баллов: `сумма задач × 1/2^(попытка−1)`;
- если минимум 4 задачи имеют результат `3–4`, ФИО студента подсвечивается зелёным;
- общий CW студента складывается по двум контрольным.

В центральном файле `CW` считается как сумма значений `S` по двум контрольным. При первой попытке максимум — 20 баллов за одну КР, при второй — 10, при третьей — 5, при четвёртой — 2.5.

### `Рейтинг`

Колонки рейтинга:

`ФИО → Практик → D → CW → Тир`

Студенты с `Прод = Нет` из рейтинга исключаются. При повторном `Прод = Да` они возвращаются автоматически.

Сортировка идёт по D, затем по CW, затем по ФИО.

### `Логи`

Колонки:

`ФИО → Практик → Практика → Задача → Номер выхода → База D → Коэффициент → Начислено D → Статус → Поправка → Дата`

Для штрафа `-` начисляется `−2` балла без коэффициента, а `Статус` остаётся пустым.

`Поправка` — ручная корректировка преподавателя в баллах для конкретного выхода. Она прибавляется к начислению D после коэффициента: `Начислено D = База D × Коэффициент + Поправка`. Для обычного выхода статус `Назначен`, для выхода после 15 — `Допса`; у штрафа статус пустой.

## 4. Файлы практиков

Каждый файл практика содержит 15 листов. На каждом листе:

- 30 студентов;
- количество задач из `practiceTaskCounts` для этой практики (по умолчанию 30);
- после ФИО — поле `Присутствие` с выбором `Да` или `Нет` у Артёма и Немата; в файле Рами этого столбца нет;
- количество решённых задач `S`;
- коэффициент;
- D за текущую практику.

В плюсовике нет столбца TG. Значения `+`, `1` и `-` вводятся только в ячейки задач. У Артёма и Немата задачи начинаются после поля `Присутствие`, у Рами — сразу после `D за практику`. Присутствие пока является информационным полем и не меняет расчёт D/CW. Скрипт не создаёт комментарии или заметки к этим ячейкам.

В каждом файле практика есть отдельный лист `Логи`. Он хранит историю изменений плюсов только внутри этого файла: ФИО, номер практики, номер задачи, состояние `Поставил` или `Убрал`, дата и время. Эти листы не синхронизируются с центральным файлом. `Поставил` окрашивается светло-зелёным, `Убрал` — светло-красным.

Выпадающих списков в ячейках задач нет.

Студент вводит `'+` вручную. Апостроф нужен, чтобы Google Sheets не воспринимал `+` как начало формулы; в ячейке отображается обычный `+`.

Практик вводит:

- `1` — обычный выход к доске;
- `-` — штраф `−2` без коэффициента.

Цвета:

- номер задачи в шапке по умолчанию — светло-жёлтый;
- номер задачи становится тёмно-зелёным, если в её столбце есть `1`;
- `+` — светло-зелёный;
- `1` — тёмно-зелёный;
- `-` — красный.

Очистка значения удаляет соответствующую запись из центральных логов.

### Разное количество задач по практикам

В начале `Code.gs` настройте один общий конфиг:

```javascript
defaultTaskCount: 30,
practiceTaskCounts: {
  1: 30,
  2: 25,
  3: 40
},
```

Номер слева — практика, справа — число задач (целое от 1 до 200). В примере на практике 2 будет 25 задач у Артёма, Рами и Немата, на практике 3 — 40. У неуказанных практик остаётся `defaultTaskCount`. В поставляемом конфиге `practiceTaskCounts: {}`: все 15 практик по-прежнему имеют 30 задач, пока вы не внесёте свои значения.

Для уже работающих Google-таблиц:

1. Обновите `Code.gs` в Apps Script общей таблицы, сохранив свои четыре ID, и заполните конфиг.
2. Сохраните код и обновите страницу общей таблицы.
3. Выберите `DM система → Применить количество задач` и дождитесь завершения. Обычная синхронизация тоже применяет изменения числа столбцов; отдельная команда дополнительно восстанавливает формулы и оформление даже при том же числе задач.
4. Проверьте нужную практику: номера задач, S и коэффициент обновлены. На остальных практиках остаются свои количества задач.

Существующие заголовки и отметки сохраняются. Новые задачи добавляются справа с номерами по порядку и пустыми ячейками. При уменьшении очищаются только заголовки лишних задач, а их столбцы скрываются; физического удаления столбцов нет. Если в убираемых столбцах есть данные или по этим задачам сохранились записи в центральных `Логах`, операция останавливается **до изменения любого плюсовика**. Сначала разберите эти записи либо оставьте прежнее количество — автоматического удаления оценок нет. Пока конфиг не применён, обработчик отметок и обновлённый мост бота сообщают о несовпадении количества задач.

Меняется и знаменатель коэффициента: для 25 задач пороги считаются от 25, для 40 — от 40. Поэтому увеличение количества задач на уже проведённой практике может изменить коэффициент и начисленное D, даже если прежние отметки сохранены.

Если используете Telegram-бота, одновременно обновите `AppsScriptBridge.gs` из его приватного репозитория в том же Apps Script-проекте. После применения конфига обновите **существующее** развёртывание: `Deploy → Manage deployments → Edit → New version → Deploy`. Так `/exec` получит новую версию обоих файлов и конфига; URL и секрет менять не нужно. Это необходимо и после следующих изменений количества задач. Создайте новый черновик или нажмите «Пересчитать». Серверный алгоритм получает список задач из моста — отдельный конфиг количества задач на сервере не нужен. Без бота Deploy не требуется.

Для создания новых XLSX-шаблонов локально генератор читает этот же конфиг из `Code.gs`:

```bash
python sheet/build_four_workbooks.py --output-dir ./generated-dm
```

Это создаёт новые файлы в указанном каталоге; для обновления рабочих Google-таблиц используйте меню выше. Без `--output-dir` генератор перезаписывает шаблоны в каталоге `sheet`.

Проверки для разработчика:

```bash
node --test sheet/test/practice-task-counts.test.cjs
python -B -m unittest discover -s sheet/test -p "test_*.py"
```

Чтобы дополнительно проверить настоящий API-мост вместе с `Code.gs`, задайте переменную окружения `DM_BOT_BRIDGE_PATH` с путём к `AppsScriptBridge.gs` из репозитория бота и повторите Node.js-тесты. Проверки используют модели таблиц и временные XLSX, не рабочие Google-таблицы.

## 5. D и коэффициент

Лестница обычных выходов:

| Номер выхода | База D |
|---|---:|
| 1–3 | 6 |
| 4–6 | 5 |
| 7–9 | 4 |
| 10–12 | 3 |
| 13–15 | 2 |
| после 15 | 0 |

Коэффициент для каждой практики считается заново:

- больше `2x/3` плюсов — `1`;
- от `x/2` до `2x/3` включительно — `0.8`;
- меньше `x/2` — `0.5`.

`x` — количество задач практики. В расчёт входят только `+` и `1`; `-` не входит.

Если коэффициент изменился после новых плюсов, он пересчитывается для всех предыдущих выходов этого студента за эту практику. Например, два выхода с базой 6 при текущем коэффициенте 0.8 дают `12 × 0.8 = 9.6` D до поправок и штрафов.

За одну практику студент получает не больше двух обычных выходов. После 15 выходов запись помечается как `Дополнительный выход`.

## 6. Тиры

| Тир | Условие |
|---|---|
| S | D ≥ 55 и CW ≥ 24 |
| A | D ≥ 35 и CW ≥ 14 |
| B | D ≥ 17 |
| F | условие B не выполнено; итоговая оценка `2F` |

Проверка выполняется в порядке `S → A → B → F`.

`Итоговая оценка` автоматически определяется по текущему тиру и категории экзамена согласно таблице оценок.

## 7. Одновременная работа

Все четыре файла могут редактироваться параллельно. Центральный Apps Script использует блокировку скрипта при записи логов и синхронизации.

Практики редактируют только свои файлы, а изменения в центральном файле распространяются обратно на файлы практиков.

## 8. Пересборка шаблонов

Для создания новых чистых файлов выполните:

```text
python build_four_workbooks.py
```

Скрипт создаст:

- `ДМобщее.xlsx`;
- `ДМАртём.xlsx`;
- `ДМРами.xlsx`;
- `ДМНемат.xlsx`.

Пересборка создаёт чистые шаблоны и не переносит текущие логи, плюсы и баллы. Перед пересборкой сохраните рабочие Google-файлы.
